## 3. 重复记录处理策略

阶段一正式重复判断键为：

`user_id + item_id + behavior_type + time`

处理规则：

- 四元组出现 1 次：正常保留；
- 四元组出现 2～59 次：全部保留；
- 四元组出现 60 次及以上：标记为异常高频/疑似恶意重复，仅保留原始输入顺序中的首次记录，其余删除；
- 阈值 60 为包含边界；
- `time` 当前仅精确到小时，因此该规则属于同小时代理规则，不能解释为分钟级或秒级重复检测。

全量统计结果：

| 指标 | 数值 |
| --- | ---: |
| 2～59 次重复组数 | 3,843,197 |
| 2～59 次涉及记录数 | 9,886,724 |
| 60 次及以上重复组数 | 0 |
| 60 次及以上涉及记录数 | 0 |
| 高频重复删除记录数 | 0 |

本批完整数据中不存在达到 60 次阈值的四元组，因此没有记录因高频重复规则被删除。

原始数据中虽然存在五字段完全相同的记录，但根据当前正式业务规则，完全相同本身不再构成删除条件；只有同一四元组在同一小时出现 60 次及以上时才触发删除。

## 6. 最终结论

阶段一清洗现采用“重复频次阈值”策略，而非无条件完全重复去重。

完整数据共 12,256,906 条，最终保留 12,256,906 条。

检测到 3,843,197 个出现 2～59 次的同小时四元组，共涉及 9,886,724 条记录，按照规则全部保留。

未检测到出现 60 次及以上的四元组，因此高频重复删除记录数为 0。

该清洗结果可作为后续 EDA、特征工程和建模阶段的标准输入。
